# SNUKDT 11기 코오롱 모빌리티그룹 캡스톤 프로젝트: 702prime 중고차 데이터 파이프라인 및 RAG 엔진 가이드

본 시스템은 702prime.com의 중고차 데이터를 자동으로 수집하여 검색에 적합한 형태로 가공하고, 사용자의 목적별 추천 점수를 산출한 뒤 벡터 임베딩을 통해 검색 엔진(Qdrant)에 적합한 데이터로 변환하는 자동화 파이프라인입니다.

---

## 1. 시스템 개요 및 작동 방식

이 시스템은 크게 **수집(Crawl) → 가공(Process) → 추천(Recommend) → 임베딩(Embed) → 로드(Load)**의 5단계로 작동합니다.

| 단계 | 설명 |
|------|------|
| **수집** | 사이트 재고 리스트를 확인하여 신규 차량을 탐색합니다. |
| **가공** | 암호화된 API 코드(예: `ex1`, `r203`)를 사람이 읽기 쉬운 자연어와 상세 스펙으로 변환합니다. |
| **추천** | 차량 스펙(에어백 수, ADAS, 연료 등)을 기반으로 5가지 목적(패밀리카, 비즈니스 등)의 적합도 점수를 산출합니다. |
| **임베딩** | 가공된 자연어 요약문(`nl`)을 OpenAI `text-embedding-3-small` 모델을 통해 1536차원 벡터로 변환합니다. |
| **로드** | 최종 데이터를 지정된 경로에 저장하고, 로컬 API 서버를 호출하여 검색 엔진 인덱싱을 갱신합니다. |

---

## 2. 주요 파일 구성

**경로**: `web-client/source/`

| 파일/디렉토리 | 설명 |
|--------------|------|
| `sync_and_embed.py` | 메인 실행 스크립트. 전체 동기화 및 임베딩, 최종 로드를 관리합니다. |
| `crawling.py` | API 호출 로직 및 데이터 매핑(암호 코드 → 한국어/영어 자연어) 담당. |
| `purpose_based_recommandation.py` | 목적별(패밀리, 초보용 등) 추천 점수 산출 로직 정의. |
| `rag_query.py` | (테스트용) 생성된 벡터 데이터를 기반으로 로컬 유사도 검색 수행. |
| `.env` | OpenAI API Key 등 환경 변수 관리. |
| `new_car_data/` | 최종 결과물이 저장되는 폴더 (`.json` 및 `_vector.json`). |

## 3. 실행 방법

### 환경 준비

1. **Python 3.x 설치**
2. **필요한 라이브러리 설치**:
   ```bash
   pip install requests openai
   ```
3. **프로젝트 루트에 `.env` 파일 생성 후 `OPENAI_API_KEY=sk-...` 입력**

### 실행 명령어

```bash
# 전체 파이프라인 실행 (크롤링 + 임베딩 + 로드)
python sync_and_embed.py
```

**참고**: 스크립트 실행 시 재고가 삭제된 차량은 로컬에서도 자동 삭제되며, 신규 차량만 추가로 크롤링합니다.

---

## 4. 데이터 구조

저장되는 JSON 파일은 섹션별로 나누어져 있으며, 각 섹션은 다음을 포함합니다:

- **`id`**: 고유 식별자
- **`payload`**: 실제 데이터 (`raw`: 상세 스펙, `nl`: 자연어 요약)
- **`vector`**: 벡터 검색용 임베딩 값 (1536차원)

### 핵심 섹션

- **`summary`**: 차량의 전체적인 기본 스펙 요약
- **`options`**: 안전/편의 옵션의 유무 (Boolean)
- **`purpose_meta`**: 목적별 적합도 점수 및 근거

---

## 5. 유지보수 가이드

### 1) 추천 기준 변경

차량 추천 점수 산출 방식이나 요구 사양(예: 에어백 개수 등)을 변경하려면 `purpose_based_recommandation.py` 파일의 `PURPOSE_CONDITIONS` 딕셔너리를 수정하십시오.

### 2) API 주소 변경

사이트의 API 엔드포인트가 변경되거나 새로운 데이터 필드가 추가될 경우 `crawling.py` 내의 호출 URL과 `build_sections` 함수 내 매핑 로직을 업데이트해야 합니다.

### 3) 검색 엔진 서버 변경

데이터 적합 완료 후 호출하는 API 주소는 `sync_and_embed.py` 하단의 `subprocess.run` 부분에서 수정할 수 있습니다. (현재 `http://localhost:8000/api/data/load`로 설정됨)

### 4) 제언

- 기존 Vector DB의 collection을 삭제 후 재생성하는 것이기 때문에 **10여초간 챗봇 사용이 불가**하게 됩니다.
- **실서비스 시 DB 이중화가 필요**합니다.
